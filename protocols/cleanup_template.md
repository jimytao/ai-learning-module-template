# 模板清理协议 (cleanup_template.md)

> **注意**：本文件是**一次性协议**。当项目第一次初始化（Phase 0）完成、用户画像（profile）写入完毕、自带阅读器及 macOS 启动脚本验证就绪后，由用户或 AI 触发执行。
> 只有在全部修改与验证成功后，才允许把删除本文件作为**最后一步**。任何检查失败时立即停止并保留本文件。

---

## 1. 触发时机与条件

当且仅当满足以下条件时，方可读取本文件并执行清理：
1. **Phase 0 确认卡已通过**：用户确认画像，且画像数据已写入 `knowledge/profile.md`、`knowledge/desire.md` 等文件。
2. **浏览器程序可用**：本分支自带的阅读器可正常加载，且 `p0_bootstrap.md` Step 3.5 校验通过（`npm test` 与 `node scripts/verify_reader.js` 均无问题）。
3. **启动脚本可运行**：`start.command` 保留可执行权限并已在 macOS 上测试可用。
4. **用户或 AI 发出指令**：「读取 `cleanup_template.md` 执行清理」或「清理模板冗余信息」。
5. **改动可恢复** —— Git 是**可选项**，很多使用本模板的人根本没装过 Git：
   * 用 `git rev-parse HEAD` 探测一次。**不得**要求用户去安装 Git，也不得把「没有 Git」当作失败。
   * **有 Git 且工作区干净** → 记录提交哈希后继续。
   * **有 Git 但工作区有改动** → 先让用户确认如何保留这些未提交改动，禁止覆盖或混入清理。
   * **没有 Git（或不是仓库）** → 先把 `AGENT.md` 复制为 `state/AGENT.md.pre-cleanup.bak`，用一句话告知用户这是唯一的撤销路径，并等其确认后再修改。该备份自此进入保护清单。

---

## 2. 清理执行步骤

AI 必须严格执行以下修改和删除操作，**严禁使用绝对行号、通配符、递归删除或目录级删除**。本协议采用白名单：未明确列出的文件和内容一律不得删除。

### 2.0 永久保护清单

清理不得删除、清空、移动或重建以下内容：

- `protocols/intake_checklist.md` 与 `protocols/p0_bootstrap.md`（以后更新画像、修改语言及审计初始化仍需要）；
- `knowledge/`、`state/`、`content/`、`templates/`、`images/` 中的任何文件；
- `notes.json`、`review.md`、`DESIGN.md`、README、启动脚本和全部阅读器文件；
- 若 §1.5 生成了 `state/AGENT.md.pre-cleanup.bak`，该备份不得删除（无 Git 时它是唯一的撤销路径）；
- `AGENT.md` 中的「更新画像」「修改解释语言」「模态切换」路由，以及 Phase 1–3、Tech Debug 和 Progress Check 路由。

允许删除的内容只有：

1. `AGENT.md` 中唯一一对 Bootstrap 锚点及其包裹区块；
2. `AGENT.md` 文件地图中唯一一行 `cleanup_template.md`；
3. 全部验证通过后，本协议文件 `protocols/cleanup_template.md` 自身。

### 2.1 改写入口路由 `AGENT.md`（高安全定位）

为了防止用户修改文档后内容发生行号偏移，AI 必须使用以下语义和锚点安全地改写 `AGENT.md`：

1. **利用 HTML 注释锚点删除初始化引导区**：
   * 在 `AGENT.md` 中定位由 `<!-- TEMPLATE_BOOTSTRAP_START -->` 和 `<!-- TEMPLATE_BOOTSTRAP_END -->` 包裹的块。
   * 两个锚点必须各自恰好出现一次，且 START 位于 END 之前；缺失、重复或顺序错误时立即停止，不修改任何文件。
   * 将该包裹块（包括这两个 HTML 注释行本身）**彻底删除**，以清除所有的初始化改造指令与说明。
2. **状态栏更新**：
   * 只改顶部「当前项目状态」一行；科目、模态与解释语言必须来自用户已确认的 `knowledge/profile.md`，不得推断。
   * 若确认值仍为空或为 TBD，立即停止，不进行清理。
3. **精准匹配清理文件地图**：
   * 在 `AGENT.md` 的文件树代码块中定位 `cleanup_template.md`，该行必须恰好出现一次。
   * 只删除这一整行；如缺失或重复，立即停止。
4. **精准替换黄金规则**：
   * 搜索并匹配第 8 条规则的字面内容（含有“*空白模板纪律（仅模板态）*”字样）。
   * 该规则必须恰好出现一次，否则立即停止。
   * 将其整体替换为：“*8. **画像纪律**：画像以 profile 为准，不编造用户未提供的信息。*”
5. **精简文档职责边界**：
   * 不删除职责表的任何行。只允许把 `intake_checklist.md` 的职责描述改为「画像更新与补全槽位权威」，其它职责保持原样。
6. **删除任何内容之前先写入初始化痕迹**（必做）：
   * 向 `state/log.md` 追加一行：`Initialized YYYY-MM-DD · Subject: … · Modality: … · Reader: built|skipped · Template cleanup: done`。
   * 追加操作已由 §2.0 明确允许 —— 保护清单禁止的是删除、清空、移动或重建 `state/` 文件，不禁止向其追加。禁止改写已有日志内容。
   * 同时更新状态栏，使该痕迹不依赖 `log.md` 单点存在。
   * 这一行是初始化的持久证据，也是 §2.3 的幂等标记。改造完成清单无法承担此职责：它位于第 1 步删除的区块之内。
7. **保留已确认的个人偏好**：
   * 不修改 `intake_checklist.md`、`p0_bootstrap.md` 或任何画像文件。禁止删除 `knowledge/profile.md` 中已经确认的值，包括主要解释语言、学习内容语言、无障碍需求、时间约束和学习偏好。
   * 保留「更新画像」路由，使用户以后可修改这些值而不必重跑完整 Bootstrap。

### 2.2 验证、审核与最后自删

1. 修改 `AGENT.md` 后先检查 diff；diff 中不得出现永久保护清单内文件的删除、清空或移动。
2. 验证以下后置条件：
   * `knowledge/profile.md` 仍包含已确认的主要解释语言、学习内容语言及其它个人偏好；
   * `AGENT.md` 仍包含「更新画像」和「修改解释语言」路由，并正确引用现存的 `intake_checklist.md`；
   * `p0_bootstrap.md`、`intake_checklist.md`、学习内容、Notes、状态文件、模板和阅读器文件仍存在；
   * §2.1 第 6 步写入的 `Initialized …` 行已存在于 `state/log.md`；
   * 项目现有校验/测试全部通过。
3. 向用户展示清理摘要和实际 diff；若用户要求先确认，则等待确认后继续。
4. **最后一步**：仅在上述检查全部通过后删除 `protocols/cleanup_template.md`。删除目标必须按仓库根目录解析后与该精确相对路径一致。
5. 任一检查失败：立即停止，不删除本文件；报告失败项，然后恢复：有 Git 时用记录的提交恢复，否则用 `state/AGENT.md.pre-cleanup.bak` 恢复。两者都不存在时，不再做任何改动并询问用户如何处理。

### 2.3 中断恢复（本协议可重入）

清理可能在改写 `AGENT.md` 与自我删除之间被中断。再次加载本文件时，必须先读取当前状态，而不是默认从头开始：

| 观察到的状态 | 含义 | 应对 |
| :--- | :--- | :--- |
| 锚点仍在，无 `Initialized` 行 | 尚未开始 | 从 §2.1 第 1 步执行 |
| 锚点已消失，`Initialized` 行已存在，本文件仍在 | 编辑成功，自删未完成 | 只重新验证 §2.2 后置条件，然后删除本文件 |
| 锚点已消失，但无 `Initialized` 行 | 执行到一半被中断 | 不要重复编辑。补写缺失的痕迹，验证 §2.2 后删除 |
| 锚点部分存在 / 重复 | 已损坏 | 停止。用 Git 或 `.bak` 恢复并报告 |

禁止重复执行已经生效的编辑 —— §2.1 每一处编辑都有「恰好出现一次」的保护，重复执行只会让流程停止，不会产生第二份副本。

---

## 3. 清理结果确认与交接

清理完成后，AI 必须向用户输出一份简洁的“项目整洁度报告”，包含：
1. **实际修改与删除列表**（删除项只能是 Bootstrap 锚点块、文件地图中的 cleanup 行和 `cleanup_template.md` 自身）。
2. **已简化的 AGENT.md 状态预览**。
3. **持久画像检查**：确认主要解释语言及其它已接受的个人偏好仍保留在 `knowledge/profile.md`。
4. **保护清单检查**：确认 intake、p0、内容、Notes、状态、模板与阅读器均未被删除或清空。
5. **初始化痕迹**：引用写入 `state/log.md` 的那一行 `Initialized …`，并说明当前使用的撤销路径（Git 提交哈希、`.bak` 文件，或「两者皆无 —— 用户选择直接继续」）。
6. **下一步行动指引**：提示用户双击 `start.command` 启动浏览器，并说「今天学什么」或「排期」正式进入 Phase 1。
